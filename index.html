Service Request GIS

A mock ArcGIS REST FeatureServer over ~850 synthetic public service requests in and around Cape Town, with a Maps SDK viewer, a cross-filtering dashboard, and 70 analytical questions written twice — once as REST query calls, once as T-SQL.

What is actually running

There is no server behind this page. The mock FeatureServer — the SQL query engine, the ArcGIS query semantics, the T-SQL dialect translation — runs inside the viewer tab on SQLite Wasm, and a service worker answers the /arcgis/rest/… requests the ArcGIS Maps SDK makes. Open the Network tab and you will see genuine FeatureServer/0/query requests with genuine Esri JSON responses.

It is the same code the local Node server runs: the viewer detects whether a real server is there and, if not, stands the engine up in the page. The REST services directory above is served that way too, so the viewer needs to be open in a tab for it to answer.

Running it locally

Node ≥ 22.16, no npm dependencies. npm start serves the real mock FeatureServer on http://127.0.0.1:3000, and npm test runs the 70 REST queries, the T-SQL equivalents, their parity assertions, and the same suite again against the in-browser engine. The repository also carries SQL Server scripts that load the identical data, so the T-SQL can be run where it was written for.

Synthetic data, generated for development and testing. No real people, addresses or records.
