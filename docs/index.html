Documentation

Three documents, written as Markdown in docs/ and rendered here. The first describes the data, the second how the questions asked of it are organised, and the third the architecture the proof of concept is actually testing.

  • Overview

    What this proof of concept is testing, the two-request architecture, what the demo shows and the three places it breaks down — the front door of the site.

  • Architecture

    The components and how they reference one another: one library source, three derivations, one engine on two runtimes — and the query library as table 1 of the service and as a view in SQL Server.

  • Data model

    The fields, the categories and sub-categories, how the generated data behaves, and the defects planted for the data-quality queries.

  • Analytics framework

    How the 70 questions are organised: the 5W+H dimensions, the five analytical layers, the coverage checklist and what comes next.

  • Query catalog

    The architecture: the query library published as a FeatureServer table, why it stores parameters rather than statements, and the three places the pattern does not hold.

  • Catalog pattern

    The argument without a platform in it: why you would make the questions data rather than code, what that costs, what it does to caching and delivery, and an honest scoring of this repository against it.
